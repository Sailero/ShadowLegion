# 当前产品盘点：送信冒险与动作构筑的分叉

审阅日期：2026-09-13。审阅对象为当前工作区源码，包版本 `1.4.0-alpha.4`。通过读取 `.git/HEAD` 与对应分支引用复核当前 **sourceHead 为 `1a37f7b947d0b9ec7f50ec19faca09baaf44bca8`**。本次没有运行 Git、测试、构建或图形进程，没有修改生产代码；只新增本文。第五地区、v5 存档与最终回局实现已经停止，不能计入现有产品。

当前最准确的描述是：**一个包含四片协作送信地区、并保留完整战斗练习系统的浏览器开发版本；两者使用相近的角色与包装，但尚不是同一套游戏成长。** 它既不是已经验证的三小时猫咪冒险，也不能因为有 50 个战斗小关，就直接称为已经成立的肉鸽成品。

本文把“源码实现”“已有验证”“尚无证据”分开。源码能够证明规则和调用存在，自动检查能够证明具体边界，图形观察能够证明某一版本的实际流程；这些都不能单独证明玩家觉得有趣、爽快、感动或愿意重玩。以下产品评价属于基于源码的设计判断，不是市场结论，也没有引用尚未取得的真人体验数据。

## 1. 玩家实际进入的是什么

当前注册了 `DeliveryScene / LakeScene / MountainScene / DesertScene` 四个邮路场景，以及 `CampaignScene / LoadoutScene / ArenaScene / GameOverScene / WorkshopScene` 战斗和成长场景。没有注册 `SnowScene` 或最终回局场景。[注册清单](../../src/main.ts#L38)

主菜单第一项进入邮路图；第二项“邮路上的小练习”进入战斗关卡；第三项“和昨天的自己切磋”进入影子模式，另有无尽、工坊、回信册、战斗续玩。菜单底部把真实邮路回信、战斗星章和暖晶放在一起。[MenuScene](../../src/scenes/MenuScene.ts#L16)

四区解锁必须依次具有真实的森林、湖、山地投递凭据；战斗通关不能解锁主邮路。雪湾虽然有稳定 ID 和后续故事线索，解锁函数仍返回锁定，地图只展示规划位置。[地区解锁](../../src/data/journey.ts#L44)、[JourneyMapScene](../../src/scenes/JourneyMapScene.ts)、[旅程凭据校验](../../src/systems/JourneyProgressManager.ts#L31)

**最具体的混淆不是模式多，而是奖励含义不一致：** 工坊把 `Meta.clearedStages / 50` 写成“已送达 … 封信”，研究前置也写“送达 N 封”；这个数字实际来自战斗小关。工坊购买的是生命、攻击、营地、技能和角色专精加成。湖、山、沙共用的步行角色固定为 ranger，移动数值固定，没有调用这些战斗加成。森林同样没有接入工坊成长。因此玩家送完一封主线信，并不会获得这套“邮装专精”承诺的成长；购买战斗移速也不会改变主邮路步行。[工坊文案](../../src/scenes/WorkshopScene.ts#L31)、[研究文案](../../src/scenes/WorkshopScene.ts#L74)、[战斗加成](../../src/systems/MetaProgressionManager.ts#L210)、[邮路角色初始化](../../src/scenes/PostalWalkScene.ts#L53)、[固定步行速度](../../src/scenes/PostalWalkScene.ts#L248)、[森林场景](../../src/scenes/DeliveryScene.ts)

回信册还有第二种兼容含义：真实投递可以解锁回信，旧战斗进度也保留阅读资格，包括旧终章文本。界面已标“旧练习旅途可回看”，但**能打开终章文字不代表主邮路已经有可玩的五封信和结局**。[故事解锁两条路径](../../src/data/story.ts#L157)、[阅读来源标注](../../src/scenes/LetterBookScene.ts#L24)

四区真正值得保留的是**伙伴必须有实际位置、玩家要用自己的移动完成合作**。湖、山、沙的小暖会沿玩家足迹或已验证的独立路线走过去、走回来，不靠远程指令瞬移完成机关。沙原把“留一个位置给朋友”的叙事落实到了两端共同展开的空间操作。[伙伴派遣与召回](../../src/scenes/PostalWalkScene.ts#L105)、[足迹安全压缩](../../src/scenes/PostalWalkScene.ts#L198)、[共同持布与可选软垫](../../src/scenes/DesertScene.ts#L149)

但目前有三处明显限制，不能被“温暖”二字掩盖：

- **轻跃是平面加速，不是有高差的跳跃系统。** 当前位置仍由平面安全区域检查；没有已实现的攀爬、滑翔、跨层路线或空中落点决策。动作帧能改善反馈，不能自动带来更深的移动玩法。[步行 update](../../src/scenes/PostalWalkScene.ts#L226)
- **不少提示直接给出答案。** 湖两片叶分别只有两个朝向，HUD 和错误提示直接写“西叶向东、北叶向北”，错误配置不能发船，并不是可试验分支水路。沙原第二题的教学文字在玩家推导前就告诉他西锚错误、绕左到上方换锚；最后一题错误提示进一步指导“往门牌右侧退、调整上下”。这能降低卡关，也可能把谜题变成执行清单，需要观察玩家究竟在思考什么。[湖叶片数据](../../src/systems/LakeVoyage.ts#L21)、[发船前置](../../src/systems/LakeVoyage.ts#L154)、[湖提示](../../src/scenes/LakeScene.ts#L125)、[沙原教学](../../src/scenes/DesertScene.ts#L19)、[沙原答案提示](../../src/scenes/DesertScene.ts#L171)
- **四区能力目前是局部机关，尚非通用叠加成长。** 森林稳桥、湖稳船、山接铃、沙拉布由不同场景和模型分别解释 E/F；`JourneyState` 主要记录完成节点和回执，没有可组合、跨区再次应用的伙伴能力系统。小暖“学会了”有故事和当前机关含义，但没有充分的后续关卡证据证明玩家会将已学技巧自由迁移。[旅程数据](../../src/data/journey.ts)、[LakeVoyage](../../src/systems/LakeVoyage.ts)、[MountainRelay](../../src/systems/MountainRelay.ts)、[PairedCover](../../src/systems/PairedCover.ts)

湖区往返尤其值得单独观察：两段船程只配置了 5.6 秒和 6.2 秒，而且允许玩家同时走岸路；真正可能占时间的是“中站→两叶→中站→收信人”的陆路和理解操作。本次不把这段路程换算成真人分钟数，也不将多走路视为新增内容。[固定船程](../../src/systems/LakeVoyage.ts#L31)、[近码头才能启航](../../src/systems/LakeVoyage.ts#L192)

## 3. 战斗部分：比“附带小练习”更多，也还不是成熟肉鸽

| 组成 | 实际已经形成的循环 | 对可玩性的支持与限制 |
| --- | --- | --- |
| 操作、防守、地形 | 玩家移动、冲刺、攻击、充能技能；同时保住自身与营地，按来路转线。软沙、潮水改变移动，灯带实际伤害双方，掩体影响射线。 | “保命还是截住冲营地的敌人”是实质决策，比只绕圈有更多位置压力。地形造成击杀/伤害会进入任务统计，不仅换背景。但实际清晰度、输入舒适度和高负载辨识未获本轮完整真人证明。 |
| 邮装与局内构筑 | 四种开局路线有真实不同基础行为；每次三选一偏向本路线、通用和技能，过滤不适用或满级项；同路线三次升级触发进化。支持暴击/溅射、双弹/穿透、盾/减速、追踪/弹射/蜂群等。 | 确实存在伤害方式与生存取舍，不能说只是外观。但是其他主路线卡被过滤，大量成长仍为百分比或次数；还不能宣传成大量自由跨流派组合。 |
| 50 个有限小关 | 固定的遭遇、不同布局和来路，通关一星，主目标与额外目标各一星；目标含营地状态、时间、冲刺、技能、地形、分工、截击、优先敌人。 | 有教学递进与反复追星理由；不是只有同一地图换数值。但布局由十种结构按章节变体生成，遭遇主要编排而非随机冒险路线，50 不等于 50 套独立核心机制。 |
| 无尽 | 五波一站，继续时保留卡组与角色，站间增加较大的升级，再循环章节地形并增加压力。 | 这是当前更接近“逐渐长成一个强构筑”的模式。长期奖励只覆盖前 100 波里程碑，之后主要追纪录；不能把无限层数当无限新内容。 |
| 影子切磋和队友 | 上一局开火、移动、冲刺、技能和承伤汇总成规则画像；画像影响队友倾向、射程/速度/目标选择，也影响对手弹数等，五档三轮试炼另有规则。E 可让队友跟随或守营地。 | “上一局习惯影响下一局战术伙伴/对手”是可证明的原型区别。没有训练算法、策略自博弈、动作精确回放、在线匹配或长期人格学习；不能用这些词承诺效果。 |

必须明确一项结构性边界：**有限战斗模式每个小关重新构筑，不是从第 1 关带着卡组一路打到第 50 关。** 第一关开局选一张，其余通常两张，波间继续选；普通新开有限关清空已应用卡，只有检查点恢复或无尽续站继承。三张同路线卡才能进化，短关中进化通常靠近后半段。它更像“带长期成长的短关防守与构筑练习”，而无尽承担了长局构筑。想转向肉鸽，需要先决定哪一个是主循环，而不是只把战斗图标放到首页。[开局草拟次数](../../src/scenes/ArenaScene.ts#L166)、[有限关清理](../../src/scenes/ArenaScene.ts#L199)、[升级后开波](../../src/scenes/ArenaScene.ts#L2307)

这里同样缺少爽感证据。命中、声音、技能动画、弹射和击退已经写入运行逻辑；是否能清楚感受到升级前后差异、是否在密集画面中仍看清威胁、玩家是否主动想再开一局，不能由特效数量或自动检查通过推出。

| 有固定小关追星、可消费的有限长期成长、跨站保留构筑的无尽。 | “无限成长、无限变化”“50 个关卡保证三小时”“已经平衡的肉鸽爽游”。 |
| 本地进度有版本校验、失败重试、待发补偿和十域备份。 | “永不丢档”“浏览器与 Steam 文件存档/云存档已打通”。 |

这些区别强调的是**项目当前有何可验证的特点**，不是与所有市面作品相比已证明唯一。相关具体实现见[CatAnimator](../../src/systems/CatAnimator.ts)、[声音](../../src/systems/SoundManager.ts)、[SettingsManager](../../src/systems/SettingsManager.ts)、[待发奖励队列](../../src/systems/CampaignProgressionManager.ts#L219)、[备份恢复与回滚](../../src/systems/SaveBackupManager.ts#L215)。

## 6. 两个方向冲突在哪里，分别最强的反方是什么

冲突并不在“温暖画面不能打怪”。温暖角色可以拥有清楚、有力度的动作反馈。真正冲突的是玩家反复做什么、为什么成长、失败意味着什么，以及一次购买要获得怎样的满足。

| 选择合作送信冒险作为主产品 | 选择暖色动作构筑作为主产品 |
| --- | --- |
| 主要承诺是人物关系、探索新地方、学会合作，完成一段有结尾的旅程。节点一次完成后保留很合理；没有惩罚也可以成立。 | 主要承诺是走位、防守、构筑变强、克服更高压力，失败后愿意以新选择重来。循环复用与高密度反馈很重要。 |
| 现有优势是四种真实局部交互、伙伴实际到位、动作与故事因果较一致；沙原有可展示的操作特色。 | 现有优势是敌人/地形/卡牌/影子/永久成长已互相调用，有限关与无尽都能结算、消费和继续；重复玩的技术基础更完整。 |
| **最强反方：** 现在可能是“按答案步行完成一次性机关”，而不是有吸引力的三小时冒险。移动无高差、提示过直白、地区能力不能自由迁移，人物主要在送到后说几段话。补一张雪地图和终章不会自动补齐世界生活感或三小时价值。 | **最强反方：** 系统多不等于肉鸽深。固定短关反复重新起步，预选路线限制组合，进化后可享受的时间可能短；无尽主要复用地图和加压。最关键的爽感、构筑差异与再来一局欲望仍无真人证据，规则画像也可能被体验成普通跟宠。 |
| 未来成本主要是高质量关卡、可推导但不晦涩的谜题、人物回应、环境叙事、可迁移能力和体验剪辑；这些不能只增加数据行解决。 | 未来成本主要是将主循环收敛、让少量组合产生显著玩法变化、敌我可读性和性能，以及随机性/风险奖励/成长速度的平衡；这同样需要大量实际试玩。 |

**我的独立判断：若只看当前已经形成的重复循环与可复用系统，战斗方向占优；若看“一段完整买断旅程”的叙事结构和可用一句话解释的协作行为，送信更容易形成统一产品。** 这不等于送信更好卖，也不支持现在丢弃战斗代码。现有证据还没有证明任何一个方向的核心乐趣已经成立；最不合理的选择是继续把两套入口、两套成长和所有时长承诺一起扩大。

因此建议先把两个原型分别展示、以相近的首次体验长度比较，而不马上续做第五地区。送信观察玩家在没有直接答案时是否能推导、是否主动关心收信人；战斗观察玩家能否感知构筑改变、为何失败、是否自发重开。两组都记录不懂、回跑、等待与退出原因，不用“喜欢可爱画风”代替对玩法的选择。若制作条件不足以持续提供人物和高质量手工关卡，合作送信的制作风险反而可能更高；若团队无法迭代平衡与密集反馈，现成战斗系统也不会自然长成爽游。

## 7. 保留、隔离和删减建议（没有执行修改）

| 范围 | 建议 | 理由与边界 |
| --- | --- | --- |
| 共同基础 | 保留暖猫动作、音效与设置、真实输入队列/失焦清除、版本保护、保存结果反馈、备份回滚。 | 两个方向都受益；保留代码也不等于当前全部目标设备已验收。 |
| 存档与旧玩家进度 | 保留各域和迁移合同。若隔离模式，提供明确旧练习入口/导出，而不是抹掉暖晶或回执。 | 产品收敛不需要以丢进度为代价。当前十域已经包含两条不同成长链，不能按 UI 数字合并。 |
| 若选择送信 | 将战斗、影子竞技、无尽和其工坊隔离为旧练习/独立原型；主邮路不展示不会生效的购买承诺。保留四区最有价值的合作原型，优先验证能力跨场景使用与提示层次。 | 不靠强制战斗、刷暖晶或更长来回路线给三小时凑时长。可保留旧文本阅读，但区别真实交信结局。 |

| 新地区与更多系统 | 暂停雪湾、最终回局和新增成长树的扩写，等方向和原型反馈。 | 这些是各自方向的后续工作，不能用继续投入来代替选择。 |

## 8. 制作复杂度与维护负担

当前成本不能只用四区或 50 关的数量理解。森林自己处理输入、移动、伙伴与暂停；后三区继承 `PostalWalkScene`，各自还有载具、铃序、布面模型及存档同步。战斗的 `ArenaScene` 同时接物理、敌人、特效、选卡、成长、目标、三模式与结算。新动作、新按键或暂停改动必须兼顾多个生命周期；实际已经出现过需要专门处理的短按、失焦、持物放下、待保存确认与跨场景输入边界。[森林输入](../../src/scenes/DeliveryScene.ts#L203)、[共用邮路输入](../../src/scenes/PostalWalkScene.ts#L149)、[Arena 初始化](../../src/scenes/ArenaScene.ts#L147)、[保存重试设计](../save-recovery-design.md)

两个成长体系也增加了持久化成本：战斗有路线、钱包、奖励账本、角色熟练度、局首检查点，邮路有 v1 森林和 v2 键上的 v4 地区记录；十域备份要验证各自版本、兼容缺域、拒写与回滚。这个可靠性工作有价值，但不会直接增加一分钟剧情或一种好玩的决策。[旅程版本与前置](../../src/systems/JourneyProgressManager.ts#L17)、[备份域与预览](../../src/systems/SaveBackupManager.ts#L11)

PC 原生发行仍有实在缺口：现有 Electron 壳已经启用隔离、禁用 Node 集成、沙箱、阻止外跳和 F11 全屏，并不是完全没有桌面基础；但它只加载 `dist`，没有应用层文件存档/浏览器迁移桥，现有 localStorage 属于各自浏览器或应用配置环境。当前设置只有音量、减少动态、自动开火与备份 UI，没有完整手柄、重绑和多语言方案。构建包标识仍有 `Shadow Legion`，与当前邮路包装不同；本版 ZIP 是 Web 发行物，不是已验收的 Steam 桌面包。[Electron 入口](../../electron/main.cjs#L6)、[桌面包配置](../../package.json#L35)、[设置契约](../../src/systems/SettingsManager.ts#L1)、[设置界面](../../src/ui/settingsDialog.ts#L42)

这意味着“先做可玩的两个原型再选”有成本控制意义：选定后可缩小要长期维护的场景矩阵、措辞和成长合同，仍保留存档兼容。现在继续混合扩建，则每一项后续可访问性和发行改造都要适配两套交互语义。

## 9. 三小时到底有什么证据

目前没有三小时的完整内容证据，也没有三小时首次体验样本。已经存在的数字分为三类，必须分开：

1. **战斗负载模型：** 既有脚本在不同输出/命中/操作假设下，把 50 关估为约 38、52、94 分钟活跃工作量；读卡另假设约 26 分钟。模型没有完整模拟治疗、召唤、技能、范围伤害、重试、迷路或真实理解时间，不能当成玩家上下界；更不能拿来填邮路时长。[既有节奏模型说明](../campaign-pacing-v2.md#L7)、[脚本](../../scripts/analyze-pacing.mjs)
2. **内容制作预算：** 三小时文档的 55 分钟探索、55 分钟操作、25 分钟协作、25 分钟对话、20 分钟可选内容是规划。山地的 8–12 分钟、雪湾的目标分钟数也只是目标，不是已测样本；当前四区不是旧 50 个战斗小关的自然延长。[三小时规划](../steam-three-hour-plan.md#L41)、[山地记录](../mountain-implementation.md#L3)、[未实现雪湾审查](../snow-prototype-review.md)
3. **运行采样与图形记录：** `SessionMetricsManager` 只保存最近 120 条每波样本，当前调用位于正式战斗模式，计的是限帧 delta 的模拟活跃时间；邮路没有对应的首次墙钟体验记录。浏览器操作轨迹证明某段走过，开发工具操作、查找控件、暂停分析所花的时间不等于普通玩家时长。[采样实现](../../src/systems/SessionMetricsManager.ts#L14)、[实际记录调用](../../src/scenes/ArenaScene.ts#L1761)

下一份有用的时间证据应来自方向明确后的完整主循环：同一版本、首次接触者、无口头提示，分别记实际探索、尝试与解题、必要往返、读对话、可选活动、停顿/卡关和总墙钟；暂停与外部打断单列。邮路还必须先具有真实第五封交付和最终回局，才能谈整作；战斗则必须先确定以短关完成、单次无尽挑战还是多次构筑体验作为“完整”。时长不足时补有意义的选择与回应，过长时去掉迷路和重复执行，不能用加血、重复开关或强制等待把表格凑到 180。

当前优先级因此是：**澄清玩家将买到的核心循环，验证自主决定与重玩/继续意愿，再决定生产哪一条完整内容线。** 两边都有值得保留的真实机制；两边也都还欠最重要的玩家证据。
