# 五地区送信主旅程：最小系统与制作顺序

只读审查日期：2026-09-12。本文只新增实施方案，未修改游戏代码或启动图形进程。依据是当前 [DeliveryScene](../src/scenes/DeliveryScene.ts)、[PostalJourneyManager](../src/systems/PostalJourneyManager.ts)、[story](../src/data/story.ts)、[故事与旅程](story-and-journey.md) 和 [三小时计划](steam-three-hour-plan.md)。森林的实际图形验收由并行任务负责；本文不将源码、自动测试或时间预算写成真人实测。

建议保留一套俯视行走与互动系统，新增三种有限状态的环境组件，制作五片相连、可回访的地区。森林教小暖停留；湖泊让玩家规划信件的运输路线；山地让信息在两处接力；暖沙让两位角色共同移动一块遮蔽物；雪湾组合前面学过的动作。每区一位主要收信人、一封有回应的主信，不把“五十关”或“每区三个纸片”作为内容配额。

当前小暖向目标点直线靠近，没有独立障碍寻路。湖泊与雪湾的远距离任务必须使用明确的可通行站点和连接段；不要直接将“目标坐标”设到树墙后再指望伙伴自行找到路。当前点击行走也会在受阻后提示重新选点，尚不是自动路径规划。

## 2. 最小系统范围

### 一套地区运行框架，不复制五份森林场景

将目前场景中的地图常量、地标、NPC、连接口和内容条件移到 `RegionDef` 数据；`DeliveryScene.init({ regionId, entranceId })` 读取白名单 ID，仍由同一场景负责输入、相机、角色和退出清理。具体文件名是计划，尚未建立。

每区只需要五个主要持久里程碑：获得本区地址线索、学会本区操作、用它解决一次变体、完成主要投递、开启返程/下一区连接。一个里程碑可以覆盖若干实际操作，不能每按一次键就存一个“任务完成”。这将原三小时计划中“每区十节点”的素材建议收敛为五个进度节点及至多两个可选发现；旧 50 个战役编号继续保留在训练支线，不强行与主旅程一一对应。

建议的最小接口：

```ts
type RegionId = 'forest' | 'lake' | 'mountain' | 'desert' | 'snow';
type CompanionTask =
  | { kind: 'follow' }
  | { kind: 'hold'; anchorId: string }
  | { kind: 'route'; routeId: string; stopIndex: number }
  | { kind: 'signal'; stationId: string; patternId: string };

// 地区/节点 ID 必须在当前内容表中，不执行存档或地图提供的脚本。
canInteract(targetId, worldState, playerPosition): Interaction;
applyWorldEvent(event, runtimeState): WorldTransition;
commitMilestone(regionId, nodeId, expectedRevision): SaveResult;
deliverLetter(letterId, recipientId, completionId, expectedRevision): SaveResult;
```

输入继续使用移动、轻跃、F 互动和 E 分工。靠近特定环境对象时，E 显示明确的动作，例如“请小暖稳住船头”；离开对象后 E 显示“呼回小暖”。先把操作动词和提示统一，供后续手柄与重绑接入，不为每个地区增加一组新快捷键。关卡条件消费世界中的成功事件，不消费按键次数。

### 三种新环境组件，加一套现有稳桥

| 组件 | 有限状态和关键行为 | 复用位置 | 控制成本的边界 |
| --- | --- | --- | --- |
| `HoldGate`，从现有稳桥提取 | 关闭、伙伴前往、实际占用、打开；伙伴离开后恢复关闭 | 森林桥、雪湾挡风页 | 伙伴必须真的抵达可见锚点；不是按 E 即达成 |
| `RouteCarrier`，新增 | 停靠、已选下一段、运输、下一站停靠；沿有限节点连接移动 | 湖泊纸船、雪湾滑盘 | **运信不载小猫**，避免新增移动平台乘客物理；信件不会落水丢失 |
| `SignalRelay`，新增 | 观察、选定图案、异地回放、补齐一声、匹配/重置 | 山地铃声、雪湾远处站点提示 | 三个以内的图形符号，字幕与声音并行；无节拍时限、无自由音频录制 |
| `PairedCover`，新增 | 放下、一端固定、玩家牵引、四向对齐、覆盖目标 | 暖沙遮阳棚、雪湾终点的挡风棚 | 使用刚性矩形与四个朝向，不做布料模拟；以目标点在棚内判断覆盖 |

共用“可互动对象、实际位置/占用、区域条件、就近安全点”即可，不需要为了五区先实现通用脚本语言、任务编辑器或任意二维物理机械。雪湾使用这四种已有组件，不再引入第五套环境规则。

小暖的操作成长先是具体场景里的新用途：留守→稳住运输→异地传讯→共同牵引→依次接力。对上一份旅程文档中的“自由脚印录制”方案，本计划做了明确收敛：首发雪湾采用设计好的 2–3 个站点队列，玩家选择下一站，小暖沿已定义连线行动。暂不加入玩家坐标轨迹采样、自由路线回放或新的自动寻路器；现有战斗画像也不被称为这些能力。

## 3. 五片地区怎样玩

### 风铃森林：先学会停下，再学会安心走开

**收信人：**松鼠栗笺。她想寄出野餐邀请，却一直等坚果饼烤得足够好。三片地址教学仅在这里出现一次；已找回的纸片不在后续地区再次被同一阵风吹散。

**地图：**保留西南邮局、西岸林间小路、风铃石、跨溪栈桥、东岸榛子小屋和南侧返程近路。在西岸增加一条清晰的树根弯路与一处能看见东岸门牌的林窗；林窗是认路和观察地标的位置，不需要新增高度系统。地图上允许先看见收信人的家，再发现如何过溪。

**操作与变化：**

1. 在已有三张纸片上学习“名字、地区、地标”如何组成住址；找到任意一张后，邮袋中能随时回看，不强制重复跑回邮局。
2. 保留现有风铃石稳桥作为第一次真正分工。反馈依次表现“小暖正在走过去”“桥已稳住”“正在等你”。
3. 扩展版在东岸的野餐门口放一个低成本变体：小暖固定被纸风卷起的门帘，棉棉从旁边绕到里面打开门扣。门扣打开后永久通行，展示“留守只是临时分工，最后仍能一起走”，不用再做三座同样的桥。

**成长：**保留跟随/留守；教学里程碑 `forest.bellCrossed` 必须在小暖实际守住石头时跨过桥的东侧判定区。新玩家不需要完成某个按键配额，老森林完成档也不被迫重修课程。

**交付条件：**地址已完整、棉棉到达栗笺门前、信件仍未交付；扩展门帘属于路线条件，不额外设“必须轻跃三次”。按 F 后同一次成功保存记录交付、下一封信和回程入口的可用条件。收到指向泡芙的回信。

**可选内容：**帮栗笺把一张有点歪的邀请贴到野餐板，改变板上的图案；林窗旁看一幅柏叔留下的旧邮路草图。不需要收满若干橡果才能进入湖泊。

**验收：**未守石时不能过桥；反复 E 不会产生通关里程碑；过桥中途呼回小暖不会卡在溪里；交信失败时原信仍可重试；成功重进后纸片不重生、近路仍开。前三项属于操作与碰撞实机验收，不能只靠一个完成布尔值的测试通过。

### 圆镜湖：选择的是信件的路线，不是再找三件东西

**收信人：**鱼泡芙。她一直记得岸边野餐的位置，想让住在陆地的朋友知道这件事。地址已经来自栗笺的信；玩家需要辨认“第三片大荷叶旁”的正确停靠点。

**地图：**环湖岸路连接 A 西岸寄信台、B 观荷中转口、C 泡芙木夹和 D 可选小花盆。岸路可徒步走通；两片可拨动的导流叶决定纸船从 B 去 C 或 D。纸船运信，棉棉沿岸行动，避免人物站在船上的新碰撞复杂度。

**操作与变化：**先在 A→B 的单段路上学习启航与停靠；到 B 后，小暖稳住船头，棉棉绕过芦苇去拨导流叶；玩家看清水纹与码头标记后再放行。综合段要求先把信送到中转口，再从另一侧调流到正确木夹。误送 D 是可返回的停靠，不是丢信或失败重读。

**成长：**`lake.anchorLearned` 让 E 在运输锚点上变成“稳住船头”。核心决策是先稳船、再改流、最后放行，不能所有叶片随便按一遍就结算。保存的教学结果来自实际完成 A→B，不来自调流次数。

**交付条件：**信件载具实际到达 C 并停靠、信件 ID 与泡芙匹配、玩家在 C 岸边互动范围内；F 将信夹上木夹并获得泡芙的回应及岚角地址。只走到 C 或只令小暖留守都不能交付。成功后开放直达 C 的回访航线。

**可选内容：**将空果酱瓶送到 D 变成水草花盆，得到泡芙画的邮票图案；它复用载具系统，但目的地和世界变化不同，不增加主线寄送次数。

**验收：**两种导流状态产生不同的下一站；伙伴未靠近船头时船不会显示“已固定”；改流不会使航行中的船瞬移；纸船抵达错误站可返回；退出重进不会把信同时放在邮袋与船上，也不会自动判为已送达。这里没有要求玩家踩水或“跳上船”。

### 云阶山：把看见的信息，送到看不见的另一边

**收信人：**山羊岚角。他总想等一件大事才写信，这次先寄出今天擦亮铜铃的小事。

**地图：**用俯视的折返坡道组织下方风向碑、被石壁挡住视线的另一侧铃架和岚角小屋。道路在同一平面可通行，坡阶只是空间表现；首发不必加入自由攀爬、跳跃高度或相互叠加的可行走楼层。两侧由明显的山口连接，已有步行和短冲刺足以到达。

**操作与变化：**在风向碑观察三个以内的图形符号，邮袋自动保留记录；请小暖去另一侧铃架回放，棉棉在当前一侧补上缺少的符号。第一段只缺最后一声；变体改为缺中间一声，迫使玩家理解顺序；综合段把正确铃声转为一个明确的风向牌，指向通往小屋的岔路。各次答案对应不同的环境反馈，不把一段解答重复执行三遍。

**成长：**`mountain.signalLearned` 开启异地传讯；小暖可选择一处已发现的铃站，沿地图定义的安全连线到达。声音附带相同图形，听不见也能完整完成；日记允许随时查看，不考短时记忆或听音辨调。

**交付条件：**综合铃序在实际铃架匹配、风向牌已转正、玩家到达岚角门前 F 交信。只有正确场景与对象发出的匹配事件能写入里程碑，乱按三次不会通过。寄往团刺的谢谢与歪帽子线索随回信开启。

**可选内容：**在邮局或山口给旧铃添一段双人和声，只改变音乐与信纸边纹；不提供通关必需的数值优势。

**验收：**错误序列给清楚的匹配提示，可立即重选；暂停和阅读时没有倒计时推进；静音、减少动态模式和纯键盘均可解；小暖跨站不穿石墙；正确答案一次匹配后开通回程山口，不要求回访者再做谜题。

### 晒被沙原：移动一小片阴凉，让世界露出地址

**收信人：**仙人掌团刺。他需要的是合适的亲近方式，软垫、一起喝茶和并排坐下都可以。

**地图：**条纹棚、绕石堆的宽窄两条路、卷叶遮住的门牌和团刺小院。晒被绳与棚柱形成可观察的空间方向；整片地区保持暖而明亮，不增加持续掉血的酷热条。

**操作与变化：**棉棉 F 牵起遮阳棚一端，小暖 E 固定另一端。玩家围着固定端移动，让刚性棚面在四个朝向间平顺转动，实际盖住卷叶时它才展开。第一处目标靠近、无障碍；第二处有石堆，玩家先从宽路搬过去，再换固定点；最后一处要求对齐门牌与门口的一小块落脚地。换固定点改变可达的覆盖范围，不是等待一个冷却结束。

**成长：**`desert.coverLearned` 增加共同牵引。棚面、两端连接线与可用落点实时可见；移动到超出约束距离时停在边界并提示“换一边牵”，不会把小暖瞬移拉过石头。

**交付条件：**正确门牌在棚面覆盖下被读清，地址确认里程碑已保存，玩家携信到达小院并 F 交付。门牌一旦读清就记录到邮袋，不因收起棚子而忘记；成功后的固定遮阳棚成为可见世界变化，回信指向芝麻。

**可选内容：**替团刺把一块软垫摆到适合聊天的位置；把遮阳棚展开成下一次野餐的公共棚。无需搬十箱材料或收满一套布料。

**验收：**朝向变化确实改变覆盖区域；玩家与伙伴未分别牵住两端时不能产生覆盖结果；只靠近卷叶或空按 E 无效；棚子不会把人物夹入实体墙；任何持物状态退出后都能从安全锚点恢复，信件不丢失。

### 晴雪湾：小暖有自己的那一段路

**收信人：**企鹅芝麻。她学会请朋友扶住箱盖，五位朋友一起写出寄给棉棉和小暖的新信。

**地图：**南侧寄信台、两段木栈道、中央滑盘轨道、背风铃站、蓝信箱与晾围巾的小院。雪是晴朗的薄雪，没有必须维持的体温；两条栈道让玩家能提前看见伙伴与滑盘的下一站。

**操作与变化：**信件放在滑盘上；小暖先稳住第一处挡风页，棉棉从另一条栈道拨动路线，滑盘抵达中站。然后玩家明确指定下一处铃站，小暖按已学的图形给出回应，棉棉确认最后一段开放。终点用已学的棚面挡住卷纸风，让芝麻扶着信箱接住滑盘。每段停靠后都保存安全里程碑，失败只重试当前小段。

**成长：**组合留守、运输、异地信号和共同牵引，形成最多三个明确站点的接力。指令面板列出“小暖现在负责哪里、下一步去哪里”，可以取消下一站并呼回。这里不新增自由轨迹录制，不要求玩家在全新第五种操作上突然精通。

**交付条件：**滑盘带着正确的信停到终点、挡风棚完成对齐、棉棉在芝麻处确认交付。五封主信都有实际完成凭据后，出现“返回晴日邮局拆新信”的终点目标；回家互动打开终章。终章观看或跳过不影响交付记录，也不要求无尽/影子试炼通关。

**可选内容：**把五位朋友的明信片摆在同一面晾绳上；根据先前已做的可选发现出现对应图案，缺少任何一项都不挡住结尾。小暖完成后仍可跟随、互动与回访。

**验收：**玩家一直站在寄信台并重复发指令不能完成；运输与玩家路线之间确有依赖；错误站点可撤回而不清空此前里程碑；中站退出后恢复在可继续的位置；最后交付与回邮局是两个可恢复节点；结局后小暖实体及常规操作仍存在。

## 4. 成长与奖励只记录有意义的改变

能力从教学成功节点派生，地区开放从前一封主信实际交付派生，回访近路从对应投递/开路节点派生。不要同时保存三套可互相矛盾的 `unlockedAbilities`、`highestRegion` 和 `storyChapter`。

主线奖励依次是新的环境操作、地址线索、居民回应和近路。每区至多两个可选发现提供邮票、装扮或世界摆设；它们属于固定内容 ID 的一次性获得，不采用无限重复交信换基础能力的经济循环。旧战斗角色、星章、暖晶、无尽及独立影子对战保持各自记录，放在邮局训练入口；主旅程通关条件不读取它们。

为了避免“学会”的动作变成空刷，里程碑事件应带上可核对的对象与结果：

| 事件 | 必需的世界证据 | 不接受的替代证据 |
| --- | --- | --- |
| `bridgeCrossed` | 过桥起终判定区、小暖占用的石头 ID、开放状态 | 按过 E，或人在东岸但来源未知 |
| `carrierDocked` | 实际载具、信件 ID、目标码头及停靠状态 | 选择过该码头、点击过启航按钮 |
| `signalMatched` | 正确站点、观察过的图形、实际匹配结果 | 累计播放三次、按铃总次数 |
| `coverObserved` | 两端处于有效状态、目标实际在棚面内、正确门牌 ID | 使用过棚子、人物经过沙区 |
| `letterDelivered` | 主信已获得、前置里程碑、正确收件对象、合法交互距离、唯一交付凭据 | 观看回信页、旧 Campaign 三星、从菜单选到后区 |

存档本身不能防止用户任意编辑本机文件；这些约束是游戏内部事件与恢复的一致性要求，不是防作弊或在线权威声明。

## 5. 多地区存档：保留 v1，派生成长，存安全落点

下面是拟定的主旅程 v2 领域格式。桌面文件路径、受限 IPC、最近有效副本与写入策略沿用三小时工程计划另行实现；本文件不把这些平台能力算作已有代码。

```ts
interface PostalJourneyV2 {
  version: 2;
  contentVersion: 1;
  revision: number;
  checkpoint: { regionId: RegionId; spawnId: string };
  regions: Partial<Record<RegionId, {
    completedNodeIds: string[];
    // 只有森林需要，迁移现有三张地址，不用于其他地区模板。
    addressParts?: ('recipient' | 'address' | 'landmark')[];
  }>>;
  deliveries: Partial<Record<
    'letter.to-lijian' | 'letter.to-paofu' | 'letter.to-lanjiao' |
    'letter.to-tuanci' | 'letter.to-zhima',
    { completionId: string; migratedFromV1?: true }
  >>;
  optionalDiscoveries: string[];
}
```

**内容约束。** 地区固定五个，主信固定五封；节点、发现、出生点 ID 均由对应内容表白名单限定，每区持久节点不超过 16 个、发现总数不超过 20 个，完成 ID 继续采用 1–120 字符的合法集合。`revision` 为有上限的安全整数。建议序列化上限 32KB；超界、未知版本或未知内容版本保护原档并提示，不能净化成一个成功空档。界面显示名可以改，稳定 ID 不随翻译改动。

**保存时机。** 收取森林地址、完成一次真实机关里程碑、到达新的安全检查点、交付和可选发现时保存；相同节点不重复写。人物坐标、影伴插值位置、冲刺剩余时间、正在移动的船/棚子属于运行时状态，不逐帧落盘。载具到安全停靠点时才更新检查点；重进后从该点的设计初态恢复未完成机关，已经完成的路线和捷径仍在。

**信件所有权。** 可携带主信从上一封交付推导，初始森林信由序章起点提供。未交付信在恢复时放回当前检查点的邮袋/寄信台；场景中的运输实例只是这封信的运行时表现，不再另存一个独立背包副本。已经交付的信不能重新装船；回信内容从交付记录派生，所以不会出现“奖励存好了但回信没领到”的第二次付款问题。

**提交边界。** 每次交付在同一领域事务里增加 `deliveries[letterId]` 和交付节点，下一封信、能力可用性及捷径由它派生。相同完成 ID、或同一封已送达的信用新 ID 重试，都返回已完成而不重复奖励。写后读回失败时界面保留“尚未确认”的提示；下一次重读如果已有该封信的凭据，直接恢复成功状态，不再次叠加进度。世界状态在确认保存后再永久改变，保存失败仍可以当场按 F 重试。

**并发与平台。** 保留现有 `save-changed` 拒绝旧快照覆盖的思路。桌面文件服务可以串行执行带 `expectedRevision` 的提交；浏览器 `localStorage` 的两次比较读不是原子的跨窗口锁，不能宣传无冲突合并。先支持单个活动邮路窗口，检测到外部变动就重新读取并明确提示。未来如实现合并，只合并已验证的单调完成集合；检查点由玩家确认，不任意选最后一个时间戳。

**v1 迁移。** 新格式先使用新存储键或桌面存档版本，保留 `sunlit-postal-journey-v1` 原始内容。验证 v1 后，把已有纸片映射为 `forest.addressParts`；原 `deliveryCompleted=true` 连同原 completionId 映射为栗笺交付凭据并标 `migratedFromV1`，允许进入湖泊。没有交付就继续森林当前进度。不得凭“已有三片纸”自动交信，也不从旧记录推断玩家完成过新增门帘/铃序等动作。已交付的老玩家无需为新教学再次锁回森林。

迁移写入和读回确认后才使用 v2；确认前继续保留 v1 可恢复。v1 内容非法、读入口失败或检测到未来版本时，不通过默认空档覆盖原件。备份导入/导出要一起认识 v2 的内容版本与上述字段；导入未来版同样拒绝降级覆盖。

**旧战役与绘本兼容。** 旧 Campaign 连续进度仍可作为已经获得的回信阅读权限，但不生成主旅程投递凭据。主线通关和地区开放只认新的实际交付。回信册应将“旧旅途可回看”与“这条邮路已送达”区分显示，避免拥有旧结局文本就跳过新冒险。新实现中 `getStoryLibrary` 应接统一的只读解锁上下文，不能继续为五地区逐个加布尔参数；剧情阅读本身仍不新增已读存档。

## 6. 先证明完整地区，再填满三小时目标

最小系统完成后，每区只放一个机关也只能证明五种循环能运行，不能自然得出三小时体验。先把森林扩为包含一次教学、一次有变化的应用、一次实际投递与可选发现的完整地区；观察新玩家是否愿意寻找地址、能理解伙伴分工、想读收信人的回应，再扩展其余地图。

沿用三小时计划的目标总量，换成真正的收信人地区：

| 地区 | 主路径制作预算 | 自然可选内容预算 | 合计目标 | 填入时间的内容依据 |
| --- | ---: | ---: | ---: | --- |
| 风铃森林 | 26 分钟 | 4 分钟 | 30 分钟 | 地址教学、观察路线、稳桥与门帘变体、栗笺回应 |
| 圆镜湖 | 31 分钟 | 4 分钟 | 35 分钟 | 辨认荷叶码头、单段运输、调流分工、综合航线、泡芙回应 |
| 云阶山 | 31 分钟 | 4 分钟 | 35 分钟 | 山路观察、图形记录、两处铃声接力与变体、岚角回应 |
| 晒被沙原 | 36 分钟 | 4 分钟 | 40 分钟 | 棚面教学、绕石选择、换锚点应用、门牌与团刺回应 |
| 晴雪湾与回邮局 | 36 分钟 | 4 分钟 | 40 分钟 | 既有能力的分段接力、芝麻投递、共同回家与终章 |
| **总计** | **160 分钟** | **20 分钟** | **180 分钟** | **制作分配，不是当前实测** |

表格不是每个机关需要耗时多久的硬门槛，也不保证这些设计一次实现就会达到时长。若玩家十分钟完成某区且觉得充实，先记录事实；需要扩充时，增加一种真实路线抉择、NPC 的后续回应或可见世界变化，并重新游玩验证。不能把步速改慢、增加相同取件量、拖长自动航行或锁住绘本文本来填表。旧战斗、读卡、无尽、影子试炼和窗口失焦时间均不计为这条主旅程的内容量。

建议按下面顺序制作，每项有明确停止点：

1. **冻结森林可玩闭环。** 当前输入、桥梁、安全返回、实际投递、存档恢复和回信入口都通过真实图形验收。只修本区确证问题，不同时上四套机关。
2. **建立地区与保存契约。** 提取地区数据、稳定 ID、v2 迁移及检查点；现森林行为应保持一致。验证旧完成者可以继续下一封，未完成者不丢纸片。
3. **做湖泊原型。** 只有三个主码头、两片导流叶、一次实际投递。玩家确实理解“先稳船再改流”后才扩充路线；不会理解就先改反馈，不先画整张湖。
4. **完成山地与暖沙组件。** 每种先做教学、一个变体和恢复测试；图形反馈与纯键盘操作成立后再加细节。三种新组件都不使用任意脚本或复杂物理。
5. **组合雪湾与回家。** 复用载具、占用、信号、覆盖状态。五信凭据与最终回家节点可中断恢复，结尾后可以自由回访。
6. **最后核验内容时长。** 沿用原计划的小规模首次游玩，记录墙钟中的探索、有效尝试、对话、可选内容、卡住/求助、菜单与离开窗口；报告版本、样本量、跳读和个人差异。150–210 分钟只是原计划的内部观察窗口，不强迫样本达标。

## 7. 合并验收清单

| 层面 | 最小验收点 |
| --- | --- |
| 地区差异 | 去掉地区配色后，玩家仍能从操作辨认“稳桥、调流、传讯、遮阴、组合接力”；后四区不再要求找三张地址纸片 |
| 路线意义 | 每区至少一处玩家能提前观察后果的选择；短路/稳路或主路/发现路线有真实空间区别；回程近路可再次使用 |
| 影伴意义 | 空按 E、按键连发、站在原地发完指令不能完成关键目标；必须出现伙伴实体行动与世界状态变化 |
| 交付一致 | 错收信人、错误码头、缺少前置或超出距离都不交付；同一封信重复 F、重进、读回失败重试均只有一个凭据 |
| 恢复可达 | 在伙伴前往、载具途中、棚面牵引、投递后未离开时分别退出重进；玩家、信件与伙伴都有可继续的安全状态 |
| 输入与反馈 | 鼠标/键盘均可完成，失焦或暂停后不残留牵引/互动输入；信号同时有声音与图形；后续统一行动层再验手柄，不提前承诺支持 |
| 内容与承诺 | 主线完成不依赖旧星章、无尽、影子试炼或可选收集；地图实装前不重命名旧战役冒充新地区；三小时说法等待该版本的首次完整游玩记录 |

本文提出的系统、状态格式和后四片地图全部属于下一步实施方案。当前可确认的是森林切片、五位朋友的绘本内容及相应的领域接口；完整五地区旅程仍需按上述顺序制作和验收。
