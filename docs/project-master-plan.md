# 暖影同行 / Sunlit Echoes：项目总纲

**方向评审优先于扩容。** [2026-09 Steam 对照与产品决策](research/direction-decision-2026-09.md)重新评估送信与清怪两条路线，建议优先验证“影伴协作送信”的单一核心样段，并将既有战斗保留为有边界的反方对照。第五地区、最终回局和额外成长系统暂停扩写，先解决入口、成长语义与玩法吸引力。建议不等于真人验证已经通过；下文保留 alpha.4 已有实现和原目标的可追溯记录，后续执行顺序以方向报告为准。

更新：2026-09-13。当前 **1.4.0-alpha.4** 是四地区浏览器原型，目标为 Steam PC 买断、约三小时的温暖布偶猫送信冒险。技术包名 `shadow-legion` 与旧存储键保留兼容。实现、自动检查、普通操作、性能和真人体验分别留证；**晴雪湾、最终回邮局和三小时完整作品尚未完成**。

## 核心体验与当前范围

棉棉负责认路、走位和亲手交信，小暖逐渐学会等待、运输配合、异地传讯与共同牵引。玩家必须看见伙伴走到真实地点，再利用它改变的环境完成自己的部分。核心不是重复发指令，而是决定“我现在去哪里、伙伴负责哪里、什么状态已准备好”。

| 地区 | 当前完整操作循环 | 小暖的新用途 | 持久完成依据 |
| --- | --- | --- | --- |
| 风铃森林 | 寻三片地址→分工稳桥→实际过桥→栗笺门前交信→近路回访 | 学会跟随与留守 | 实际森林交付凭据 |
| 圆镜湖 | 叶舟载信→岸路调流→中转停靠→再次稳舟与选流→信箱停靠→泡芙收信 | 伙伴稳舟时，玩家可去另一处改变路线 | 两次实际停靠及湖区交付 |
| 云阶山 | 观察铃谱→小暖走独立路线→两次不同顺序接铃→开山口→岚角收信 | 回应能让伙伴继续做自己的部分 | 两个接力匹配及山地交付 |
| 晒被沙原 | 分工扶棚→拿布展开→绕石换棚脚→门牌与叶片同时乘凉→团刺收信 | 与玩家共同决定一块遮阳布的位置 | 三处匹配读字及沙原交付 |
| 晴雪湾与回家 | 尚未实现；拟用共同扶运与拐弯路线完成最后一封信，再回邮局成为收信人 | 从等待每一步指令走向按约定照顾自己的那段路 | 尚未建立最终节点，不伪造雪区或结尾完成 |

四区有可运行源码和存档契约，不等于四区最终普通流程已经验收。主旅程按森林→湖→山→沙的真实交付解锁，雪湾继续锁定；旧战役星章、看过故事或编辑场景入口都不是正常主线完成条件。

晒被沙原本轮详见 [实现记录](desert-implementation.md)。刚性布面随猫的真实位置连续转动，需要整片目标连同边界余量都处于阴凉中；不是随便转四次即可过关。碰石或过长后布角留在最后合法位置，E 先放下再召回，错误西棚可撤回并改派东棚。匹配后立即放下布面，未确认保存时留在待存状态；不把走远的猫牵成跨地图长布。

## 操作、反馈与暖色方向

WASD / 方向键与点地直线行走并存，Shift / 右键轻跃，E 分工或召回，F 近场互动，Esc 暂停。所有地区沿用同一组主要动词。点地没有自动求路，轻跃没有高度或越墙能力；地形要能从画面中读出，错误尝试回到安全位置，不扣生命或丢信。

美术围绕奶油小路、温暖纸纹、松软植物、云海与条纹遮阳棚展开。沙原地面、石堆、棚屋与仙人掌团刺采用程序绘制并缓存，与安全几何共用地图数据。新版猫动作在待机、行走、轻跃、举爪基础上加入 `hold` 与 `carry`：手臂扶住布角，移动时脚步、尾巴和邮袋继续动作；没有通过摇动整张角色图代替持物姿势。方向、动态舒适度和手感仍须实际试玩。

山地音符同时有图形与角色顺序，沙原有布边、卷叶勾选和近场文字；静音不应丢失解谜信息。音频自动调度、模型正确和没有运行错误都不能替代真人听感或可访问性验证。

## 成长、回访与时长

主线成长是已学分工、下一封地址、居民回应和可返回的路线，不加入反复寄同一封信刷基础数值的要求。三个可选发现为湖边野餐垫、云纹明信片与小暖的第六块软垫，均不阻挡主线。当前能力主要在对应环境中发挥作用，尚不能宣传为全地图自由组合的伙伴系统。

主线重玩价值仍须验证：玩家回访是否看到有意义的回应，错误选择是否能自然恢复，以及不同路线是否值得主动尝试。现有单次谜题、练习关数和已写好的十六页故事，都不能补算为三小时可玩内容。雪湾及可恢复的最终回局节点仍需制作。

[三小时计划](steam-three-hour-plan.md) 的时间分配与 [原地区方案](region-implementation-plan.md) 是制作预算。原方案中的四向遮蔽已由本轮连续朝向布面取代；现有实现见各地区记录。[雪湾评审](snow-prototype-review.md) 只是下一阶段方案，其 10–15 分钟预算也尚未实测。后续需收集首次游玩墙钟，分别记录探索、有效尝试、对话、可选支线、卡住/求助和离开窗口；不靠强制等候或拉长敌人生命凑时间。

## v4 主旅程与十域备份

主旅程仍使用 `sunlit-postal-journey-v2` 键，内容升级为 **v4**。合法 v2/v3 读取时只在内存迁移，首次成功修改再写 v4；旧版各有严格内容白名单，不能夹入后续地区内容。森林 v1 原始字节保留，仅从真实投递凭据单调合并；旧战役不解锁主线。

沙原按 `coverLearned → courtyardAligned → addressRead` 顺序保存三个节点；派生 `trailhead / stoneCamp / courtyard / mailbox` 四个安全恢复点。所有节点和交付都写前重读、写后读回；检测到并发变更、拒写、丢读回或未来格式时，不宣称成功。它是本机同步存储的冲突检测，不是跨标签页原子事务保证。

匹配未确认时只保留本场景待存结果，F 重试不重做谜题，也不在同一按键中交信或收可选物；E 不能取消待存成功。若写入已经完成但确认读取失败，重试幂等确认原节点或同一回执，不再次写入。尚未落盘便离开或刷新，仍只能恢复到上一个已确认节点；不保存动态布姿、半段铃序或人物坐标。

十域备份包含成长、练习路线、起点续玩、设置、成绩、影子纪录、教程、波次样本、森林邮路及主旅程。备份容器仍是 v1，内部主旅程支持 v2/v3/v4；旧九域缺失主旅程时保留当前记录。预览显示地区投递与湖/山/沙安全点；确认前不写，失败尽可能回滚，活跃邮路禁止恢复。原生文件选择、下载及 v4 完整 UI 往返仍待本轮图形验证。[恢复设计](save-recovery-design.md)

## 保留的练习系统

五章五十关、无尽巡游与五阶影子切磋继续作为邮局训练入口，四个旧角色对应四套邮装。战役关卡有独立地形、遭遇和三星任务；无尽以站点推进；影子由本机移动、开火、闪避等统计驱动规则决策，不是在线玩家或学习模型。

练习成长保留三项五级装备、六项研究、每角色七级熟练度及三套有代价的专精；暖晶单钱包、消费上限、首通与提星、按凭据补发规则见 [成长设计](progression-design.md)。这些循环提供可选挑战，主信与结尾不要求练习通关。

`analyze:pacing` 仅估计旧战斗的敌人负载。约 38 / 52 / 94 活跃分钟是不同假设的模型结果，单波本地采样也不是送信墙钟；不得用它宣称主线已达到三小时。[战斗节奏报告](campaign-pacing-v2.md)
