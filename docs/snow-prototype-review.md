# 晴雪湾与最终回邮局：原型设计评审

评审日期：2026-09-13。本文是下一阶段的实施建议，**未实现雪湾生产代码、未运行图形或真人试玩**。雪湾加回邮局按 **10–15 分钟首次体验预算**收敛；这不是实测时长，也不能证明完整三小时内容或 Steam 发行准备已经完成。

依据当前 [故事与角色](../src/data/story.ts)、[地区实施计划](region-implementation-plan.md)、[PostalWalkScene](../src/scenes/PostalWalkScene.ts)、[湖区](../src/scenes/LakeScene.ts)、[山地](../src/scenes/MountainScene.ts)、[沙原](../src/scenes/DesertScene.ts) 与 [PairedCover](../src/systems/PairedCover.ts)。本文不引入外部作品的事实或素材。

## 1. 推荐的核心：一起扶运，会拐弯的两端

让棉棉扶住小雪盘前端，小暖照顾尾端，沿连续冰道把芝麻的旧明信片盒送回蓝信箱前。玩家需要提前收步、把前端带向弯道外侧，并在织物垫上停稳。小暖沿可见的点线走自己的尾端路线，发现前端停下就一起稳住，抵达最后一站后主动去扶箱盖。

**可玩性来自三个彼此可见的量：小猫的滑行方向、雪盘的真实朝向、尾端正在走到哪里。** 冰上转向会留下弧形爪迹；箱体偏向内弯时，棉棉绕外一点便能腾出位置；两端进入停靠垫，滑盘才停得踏实。没有等待进度条、反复按键次数、体温或损失信件的惩罚。

与前面四片地区的关系：

| 既有经验 | 雪湾复用的部分 | 本次真正变化 |
| --- | --- | --- |
| 森林：伙伴实际到位才扶桥 | 到位、留守与召回规则 | 最后由小暖主动去扶箱盖，仍须实际走到支点 |
| 湖区：信件运输、到站确认 | 物件有唯一位置；停靠后保存 | 雪盘不按计时自行驶完整路线，位移来自两只猫当下的实际扶运 |
| 山地：小暖走独立的明确路线 | 路线可见、按经过的路线召回、不能穿地形 | 一次约定后，小暖自行照顾尾端并在拐弯时收步；玩家不用每个路点再按 E |
| 沙原：两端握持与实际位置校验 | 握点、放下、超出范围时温柔处理、持物姿势 | 两端都在移动，刚性雪盘的位置和扫过的空间需要通过弯道；不再用覆盖面积判目标 |

不把沙原矩形换成白色再覆盖两张纸。这里的成功事件是“整个雪盘实际运到并停进下一块垫子”，不会由阴影、颜色或覆盖两个目标产生。旧计划里的“湖船运输 + 山铃 + 雪地挡风棚”收敛为一条运输主线，终点只短暂复用扶稳能力，避免做四个旧谜题的拼盘。

## 2. 故事因果与小暖的独立性

保留现有约定：收信人是**企鹅芝麻**，地址是**画着太阳的蓝信箱**；团刺送来一块软垫，芝麻需要有人帮忙扶箱盖。小暖在沙原发现的“第六块软垫”属于它自己的座位，是可选记录，不能被此处消耗或变成主线前置。

入口蓝色小告示写：“旧明信片晒好了，我想把这一盒搬回门廊。可以帮我扶另一头吗？——芝麻。”团刺的礼物垫在盒底，箱中只露出森林叶签、湖边木夹、铜铃拓印和条纹信角。沿路物件关系清楚：正在搬的是芝麻的旧明信片盒，棉棉自己的邮袋仍装着要亲手交付的信。

第一段，小暖等棉棉明确分工；第二段，它会说“转弯时我照顾后面，你慢下来我也慢下来”，随后按约定路线行动。到最终停靠垫确认保存后，箱盖被柔风抬起，小暖自己走向支点：“这一角，我来。”它不能瞬移或在还未到位时让箱盖稳定。E 仍能取消、召回；取消后可在箱旁重新 E 分工，不剥夺玩家控制。

F 交付时展示软垫放入蓝信箱前的小凳、芝麻收到信、旧明信片盒整齐地停在旁边。芝麻的回信把下一条地址改成“晴日邮局，门廊第二张小凳子，棉棉与小暖收”。终章不是再接一轮物品清单，而是两位邮差真正成为收信人。

现有 `letter-snow` 中“请邻居扶箱盖”的句子应在实现时复核角色称谓：可以保持它叙述此前请邻居帮忙的经历；若要直接对应本次两猫操作，改成“请朋友扶箱盖”。不能把小暖无说明地写成另一个未出场人物。

## 3. 连续控制规则：一套主机制，两次变化

### 3.1 第一段：宽冰道与第一块停靠垫

1. 在雪盘后端附近 E，请小暖沿真实安全路线走到尾端；地面显示它的脚印路线，而非完成勾。
2. 小暖到位后，棉棉走近前把手 F 拿稳。未到位时把手标“等小暖”，未分工时标“先 E 分工”。
3. 棉棉走过一段宽冰面和缓弯。小暖按棉棉前进的距离照顾尾端；松方向、反向收步、向外带头都会改变实际路径。
4. 织物垫的短绒纹与冰面明显不同。整个雪盘进入垫内且速度已足够低，F 才是“停稳这一站”。成功保存后展开下一段路线标记。

先让玩家看见“滑一点、收住、停稳”的效果，不在第一段布置窄缝、交叉路线或需要轻跃的缺口。能够在同一块大垫上反复拿放试手，不重复写主线节点。

### 3.2 第二段：S 弯的前端与尾端

小暖先沿旧能力提供的短路线到第二段尾把手。棉棉 F 扶前端后，小暖继续执行已经看得见的尾端路线，遇到棉棉收步就留在当前可站位置。玩家不需要在运动中切换角色，也不需要对着远处按 F。

弯道内侧有两块清楚可见的圆雪石。小猫本身能从内侧走过，但长方雪盘会扫到内侧石头，必须让前端走得稍外一点，再等尾端真正转过来。这里的“等”是观察正在移动的伙伴并调整自己的走位；站在原地不会自动获得通关进度。宽外弯始终提供完整解法，不把贴石的轻跃捷径作为必需条件。

判定失败前先让雪盘前沿轻轻抵住石头、速度归零，并指出“前端往外一点，尾端就转得过来”。保持最后合法姿态，可沿原方向退出来；确实滑出安全地面时才温柔回到最近的已踏稳垫子。不演出明信片散落，不强制重跑第一段。

### 3.3 终点：扶箱盖，空出另一只爪

第二次到站保存后，雪盘留在邮台。小暖主动沿一小段清楚的路线去扶箱盖；棉棉绕到芝麻一侧 F 交信。箱盖由小暖当前实际在位状态决定，召回时软软合上，不压住角色、不封死通路。

交付条件同时满足：第二次停靠已落盘、小暖实际到达支点、棉棉靠近芝麻、尚无雪湾回执。只带猫绕干路先见到芝麻、站在远处等、打开回信册、累计按 E/F，都不能替代运送与亲手交付。真实回执落盘后可回访聊天，箱盖不再成为重复阅读的障碍。

### 3.4 键鼠与初始参数

以下数值是可调的实施起点，不是经过真人验证的手感参数。

| 输入或状态 | 建议行为 |
| --- | --- |
| WASD / 方向键 | 沿用方向输入；冰上先加速再转向，反向输入明确收步 |
| 左键点地 | 仍是直线目标，不声称自动寻路；进入目标刹停距离时主动收速，不能在目标两侧来回打摆 |
| E | 就近建立一次尾端约定；已分工时放稳当前物件再召回；走向箱盖的自主行动也可取消 |
| F | 近前把手拿起/放下；实际进入垫子后停靠；近芝麻交付。保存待确认时优先且只重试保存 |
| Shift / 右键轻跃 | 空手保留既有短冲刺，仍不能跨越非法地面；扶运时不冲刺，提示“先放稳雪盘，空出爪子再轻跃”，维持扶运姿势 |
| 干路 | 保留约 220px/s 的现有直接响应 |
| 冰上空手 | 建议上限 180px/s；起步加速度 420px/s²；松方向减速 240px/s²，满速停距约 68px；反向刹停加速度 600px/s² |
| 两端扶运 | 建议上限 135px/s；手柄间距约 160px，允许少量绳把手松弛；不能让一只猫先跑离整段冰道 |
| 织物停靠垫 | 强抓地、清楚可见的减速；F 停靠判低速阈值，建议不高于 12px/s，且整个箱体在垫内；无连续停留计时 |
| 暂停 / 失焦 / 退出 | 清冰面惯性、轻跃状态和点击目标；暂停时整个扶运模型冻结，恢复不重放上一次 F/E |

轻跃拒绝发生在动作启动之前，不要触发冲刺动画却暗中锁住位移。原型不新增“抱箱跳跃”，也不以禁用正常走位来惩罚玩家尝试既有按键。

建议世界 **2300×1650**，所有坐标为世界像素；正式实现统一写进 `data/snow.ts`，绘画、角色与雪盘安全判定共同导入。下面是实施起点，**还未做可达性或整箱扫掠验证，不能直接当已验证碰撞数据**。

| 箱盖支点 / 玩家交信侧 | 小暖 `(2080,405)`；棉棉可站 `(2180,445)` | 显示两边分工；短路线实际可走，不穿信箱实体 |

| 可选合照角 | `(870,690)`，半径 110，接干路 `(650,660)` | 主路以外的小片宽冰面，没有必须跨越的窄桥 |

主路地面是日光下的淡蓝灰冰，边界是奶白雪沿；干路用奶油木板、燕麦色短绒垫和杏色路桩。海面只在边缘，不把画面变成另一片圆镜湖。暖桃色窗光在白天仍能看清；芝麻是圆润企鹅、晾成旗子的围巾、太阳蓝信箱三者形成收信地标。

胶囊通道、圆垫、雪石实体、箱盖实体和可运输地面应分别有明确定义。小猫可走的矮台阶不等于雪盘能爬上去；这种差异只放在有明显阶沿的干路连接口，禁止在平坦无标记地面设置隐形“不能运货”区域。

摄像机继续跟随棉棉，S 弯应确保尾端在当前画面范围内。尾端离屏时先给稳定的边缘方向与距离提示；原型不应依赖玩家对不可见物件作精确转向。四处关键站在 1024×768 逻辑画布上检查顶栏 y≤102、底栏 y≥630 的遮挡，不能只看整个世界的缩略图。

## 5. 模型与现有框架的实际接点

建议新增一个小型纯模型 `SnowEscort`，输入真实角色位置、当前输入意图和有效 delta；输出当前雪盘姿态、可接受的移动、尾端下一步、到站事件。它组合现有实际路线与持物经验，但**当前 `LakeVoyage` 是按路线航行，`PairedCover` 是固定端覆盖，二者都不能原样改名当雪湾模型**。

雪盘主体先用固定约 `100×70px` 的圆角刚性矩形，绳把手连接两猫；箱体中心和角度来自两猫实际端点。缓冲范围只能体现把手的少量松弛，不能像遮阳布那样任意拉长主体。边界同时检查角色脚下、主体四角/边和这一帧扫过的范围；两端安全不代表箱体没穿石头。

尾端沿有限节点逐段行动，进度受前端真实进展和握持距离限制。只看当前段与下一相邻段的投影，并限制单次可移动距离；不把小猫碰巧走到另一处冰弯解释成小暖可以跳过中间路。每段可以无限暂停，没有时间窗。撤销走回实际已走过的后端路线，再接上棉棉脚印。

| 现有接口 | 可直接复用 | 需要明确补的最小接点 |
| --- | --- | --- |
| `beginWalk / isSafe / recoveryPoint` | 相机、PC输入、HUD、已走脚印、安全恢复 | 雪湾必须维护“已踏稳干垫”恢复点；不能每帧把冰面当前位置都当干垫 |
| `adjustWalkVelocity` | 按地面类型计算速度 | 读取点击目标剩余距离才能提前刹停；当前钩子只有归一化后的速度，不能声称已支持精确点地收步 |
| 当前 `clearControls` | 暂停与失焦去重、清目标 | 它是私有方法且不知道子类冰惯性；需一个空默认的清理通知或等效有限接口，确保惯性及扶运临时状态同步清理 |
| `sendEchoRoute / recallEcho` | 走到约定点、真实路线召回 | 当前跟随步长写在基类 update 内，需一个默认不改变行为的尾端步长约束钩子；小暖等前端或转弯时必须在原始移动提交前停住，不能先走再瞬移回去 |
| `CatAnimator.setHolding` | 两猫举爪、静止与行走分层动作 | 用真实速度驱动扶运动作，运动打断庆祝；拒绝轻跃时也不播放假冲刺 |
| Journey 节点与备份 | 确认后落盘、拒写保护、幂等 | 增雪湾合法节点、前置和恢复点；旧版本允许列表不能自动接受雪湾记录 |

任何运动钩子默认保留湖/山/沙原行为，并用已有场景回归检查。不要在 `tickJourney` 末尾直接改 `echo.x/y` 覆盖刚发生的基类移动，否则路径记录、召回和动画速度会互相矛盾。

静态雪地和地标使用按 texture key 缓存的 Canvas，重进复用。动态层只画当前雪盘、短爪迹与箱盖状态；固定路标和字不每帧重建，历史轨迹有长度上限。减弱动态设置关闭冰晶闪动、镜头震动与庆祝弹跳，保留爪迹方向、物件朝向及必要移动信息。静音时，停稳、尾端就位和箱盖扶好均有文字/图形。

## 6. 保存节点、可选发现与防卡关

建议主线只增加两个运输节点；箱盖属于交付时的实时条件，不再加一个“按 E 成功”持久任务。

| 记录 | 必要的实际事件 | 重进后的安全恢复 |
| --- | --- | --- |
| `snow.sunBenchDocked`（拟定） | 前后端都实际参与第一段、整个雪盘在中站垫内、低速 F 停稳并读回确认 | 两猫与雪盘在中站的固定安全姿态，不重跑第一段 |
| `snow.mailDeckDocked`（拟定） | 已有第一节点，第二段实际运到邮台，按同一停靠规则确认 | 雪盘唯一地位于邮台，猫在南侧安全脚点；箱盖分工重新实际建立 |
| `deliveries.snow.completionId` | 两节点已经落盘，棉棉近芝麻、小暖实际扶盖、F 交付 | 邮台/收信状态保留，解锁芝麻回信与回邮局入口 |
| `snow.twoSignatures` 可选发现（拟定） | 中站后去合照角，两猫按各自的小脚印位站好，棉棉 F 收好“两个名字”的合照 | 只留发现记录，不改变运输进度或终局条件 |

可选合照角复用实际分工：E 后小暖沿短而可见的弧线走到自己的脚印格，棉棉站另一格，两个格子都实际有对应角色才可 F 留念。反馈是一张分别标了“棉棉”“小暖”的小画，呼应最后信封上的两个名字。没有照片碎片数量、额外奖励货币或限时踩格；忽略它可正常交信。

保存待确认时保留同一次停靠事件，F 只重试，E 不取消待保存结果，也不能启下一段。界面分别写“已停稳，保存待确认”和“到站已保存”；写成功但读回失败后重试，只确认原节点。落盘前离开/刷新可能丢掉当前小段，必须明确提示；不能承诺浏览器拒写时仍能保存。

主动放下时雪盘留在最后合法位置，两端把手仍能步行接近；E 召回会先放稳，不把盘子拉过石头。若任一端越界、瞬时输入异常或当前姿态无法继续，清两猫速度/轻跃/点地目标，将两猫与雪盘一起放回最近实际踏稳垫的预置安全姿态；已确认节点、信件和可选发现不丢失。干路始终能通向当前停靠点，不能要求穿过雪盘实体去重新握把手。

继续使用主旅程同一存储域，下一内容版本若升为 v5，应保留 v2/v3/v4 的各自合法范围并在首次成功修改时迁移；旧四区记录只开放雪湾入口，不补雪湾节点或回执。备份仍可使用当前十个白名单领域，主旅程内部新增雪湾校验与预览；不为了一个地区任意增加独立存档键。活动、暂停或休眠的 SnowScene 与回邮局场景都纳入恢复存档的场景边界。

## 7. 最终回邮局：两位邮差，收到一封信

**开门条件只能是森林、湖、山、沙原、雪湾五个连续真实回执。** 当前 `story.ts` 还兼容旧 Campaign 连续成绩解锁文本，包括 epilogue；不能把 `story.unlocked` 直接拿来开放实际终局。旧练习文本回看若保留，应继续明确标为旧练习回看，实际邮路入口与完成提示使用独立的五回执判断。

第五封保存成功后，在邮路图和菜单出现“这一封，写给我们 · 晴日邮局”。不突然切走雪湾，也不强制看完回信才能操作。芝麻处 F 可回访；玩家选择回家才进入一个小型可走门廊。

建议 `HomecomingScene` 复用步行框架，世界 `1200×900`，入口 `(260,650)`，宽 170 的门廊路经 `(530,620)→(700,470)→(820,430)` 到第二张凳子；柏叔脚点 `(960,350)`。没有新谜题和需要来回搬运的任务。棉棉靠近凳子时，小暖自己走 `(740,490)→(780,440)`，扶住风掀起的信角；玩家仍可移动和暂停。

F 坐到凳旁，才打开现有 `epilogue` 三页。Right/Left 翻页、R 从第一页开始、Esc 合上，返回同一门廊安全处。最后一页结束后，两只猫各拿一支笔，小暖留下自己的爪印，提供“再去看看朋友”和“回到邮局菜单”。不给新奖励，不清旧地图，不把之后的回访变成重新投递。

入口可完全从五回执派生，不必新增一个必需的“终章读完”存档节点。若未来保存阅读偏好，应与主线成就条件分开；尤其不能把需要在交信之后才能获得的节点放进 `JOURNEY_NODE_IDS.snow` 的交付前置，造成“先交信才能读、先读才能交信”的循环。

扩展 `StoryReturnScene` 与返回参数白名单时只接受固定的 SnowScene/HomecomingScene，进入场景仍重读真实存档。传入 `{completed:true}`、`checkpoint`、旧练习 stage 50、打开书再返回，都不能生成实际回执。重新进入可以再坐下读信；不强迫重演扶箱盖或重复结算。

## 9. 预算、完成定义与取舍

主线预算约 9–13 分钟，含可选内容约 10–15 分钟。路程本身只需较短时间，预算主要来自理解控制、真实试走、人物反应与阅读；若盲测只玩了四分钟，应如实记录并改进有意义的变化，不能加等待、加重复搬箱或把自动化时间冒充真人时间。

本片制作优先级：先证明“冰面收步 + 实际尾端 + 整物体转弯”好玩且可复原，再做终点扶盖与真实保存，最后补回邮局表现和可选合照。若有限移动钩子无法保持基类可靠，应先缩短为一条宽弯运输演示验证控制，不把缺失的连续操作换成自动航行后按 F 领奖。

完成此原型最多意味着第五片地区与可回玩的终章已经有可验证流程。完整三小时节奏、真人长期体验、全局美术统一、桌面文件存档、手柄与重绑、Steam 内容和发行验收仍需要独立完成，不能由五地区数量推导。
