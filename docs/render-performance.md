# 静态花园绘制成本与缓存验证

2026-09-12，1.3.0-rc.2。以下是本机隔离 Electron / Chromium 的测量，不能替代目标浏览器、普通可见窗口或最低配置认证。

## 发现与对照

第一份完整持续运行持续 1209.843 秒，无运行错误，但帧间隔 p95 为 33.4ms。敌人和弹道更新的 p95 各约 0.1ms，不能由此认定慢帧来自这两个循环。[持续运行原始报告](qa/1.3.0-rc.2/soak.json)

`drawArena` 虽只在场景创建时调用，其静态 Graphics 仍保留绘图命令；Phaser 的 WebGL Graphics 渲染路径每帧遍历这些命令、处理圆弧并三角化填充路径。花草、道路和营地底纹因此持续产生 CPU 提交开销。

使用 [render-profile.cjs](../scripts/render-profile.cjs) 分别记录 Game.step、场景、物理、Arena.update、渲染和静态地面对象的同步 CPU 时间。每段预热 5 秒、采样至少 20 秒。实际敌人出生后，将同一个场景暂停在 Scene Systems 层，再依次测量地面显示、仅隐藏静态地面、恢复显示；三段的冻结显示状态指纹一致。截图只在采样结束后保存。

| 同一冻结场景的对照 | 缓存前 | 缓存后 |
| --- | ---: | ---: |
| 静态地面平均 CPU 提交时间 | 7.436ms | 0.0049ms |
| 隐藏地面后，整帧 CPU 平均减少 | 7.185ms | 0.340ms |
| 地面占可见场景渲染 CPU 时间 | 65.4% | 0.12% |
| 显示 / 隐藏 / 恢复的 rAF p95 | 16.8 / 16.7 / 16.8ms | 16.7 / 16.7 / 16.8ms |

[缓存前完整报告](qa/1.3.0-rc.2/render-before-cache.json)、[缓存后完整报告](qa/1.3.0-rc.2/render-after-cache.json) 的八项协议检查均通过，错误为空。各次运行内部对照状态相同；两次运行的敌人位置与宿主机负载并非完全一致，不能把它们当成严格相同的跨版本帧率基准。

活跃场景的整帧 CPU p95 另观察到 14.7→6.2ms，渲染 CPU p95 为 14.2→5.7ms。这些是包含关系的同步提交时间，不能相加，也不是 GPU 执行时间。约 0.005ms 是多帧平均值，低于单次 `performance.now()` 的有效分辨率，不能解读成每一帧都有如此精确的耗时。

## 实现与资源所有权

静态 Graphics 在建图时生成 1600×1200 贴图，以同深度 Image 显示，随后销毁原 Graphics。动态潮汐、危险区、粒子、角色与碰撞几何继续独立更新。场景关闭时释放其拥有的缓存；如果创建缓存失败，保留原矢量背景供继续游玩。

[五十关缓存检查](qa/1.3.0-rc.2/ground-cache.json) 逐关创建真实场景，确认恰好一张 1600×1200 缓存、旧 Graphics 已销毁、碰撞几何不变，并在每次回营后确认纹理已释放。五章代表关在同一冻结场景中分别捕获原矢量与缓存画面，已检查画面内容与边界；Canvas 与 WebGL 的边缘抗锯齿可以略有不同，未声称像素完全一致。

每张缓存的 RGBA 像素数据约 7.32MiB；这只是像素量估算，不是 JS heap、进程内存或总 GPU 占用。缓存版持续运行 1207.134 秒，rAF p95 16.8ms、最大 100ms，JS heap 峰值 150.2MiB，四阶段强制 GC 后 62.9–63.8MiB，每个活跃战场采样恰好一张地面缓存。[完整报告](qa/1.3.0-rc.2/soak-cached.json) 早于最后的营地不可推动修复；它不包含营地位置断言，不能证明最后固定版的完整验收。最终结果以 [发行准备](release-readiness.md) 为准。

## 复现

先运行本机开发服务，再在没有其他图形测试的时段执行：

```powershell
$env:SUNLIT_RENDER_PROFILE_RUN = '1'
npx electron scripts/render-profile.cjs
npx electron scripts/ground-cache-smoke.cjs
```

输出写入各自的 `.cache/` 临时目录，包含逐帧数据、统计、状态指纹及原始截图。脚本只操作独立 QA 实例；隐藏地面对照、生命补充和预设路线访问不属于正常玩家体验。
