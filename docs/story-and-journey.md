# 棉棉与小暖：回信旅程

设计基准：2026-09-12。目标是约三小时的温暖送信冒险；三小时是产品目标，需要由完整内容和真人游玩记录验证。本文不把绘本阅读时间、旧战役波次数或首个森林切片时长换算成已经完成的三小时游戏。

## 这一程为什么值得走

布偶猫棉棉从晴日邮局出发，把地址不全的旧回信重新送回朋友之间。一阵爱折纸的风把正在整理的信件卷乱了；棉棉找到的每一条地址，都指向另一个仍然记得对方的人。老邮差柏叔健在，在邮局整理线索、接收新信、等两位小邮差回来。

棉棉的邮袋吸收了脚步与善意，形成同行回声“小暖”。它最初模仿，后来学会停留、分工和主动帮忙。故事结尾，棉棉与小暖共同收到五位朋友的新信，一起写回信、准备下一次出门。小暖不会牺牲或消失；故事的温暖来自关系重新开始，而不是用失去换成长。

玩家的核心选择应当是“收信人住在哪里，需要什么，我和小暖如何分头把信送到”。一封信的地址决定探索路线，收信人的需要带来新的环境动作，新的动作又打开能回访的近路。折纸风卷起的叶团、纸片与自然阻碍可以被友好拨散；动物居民是交流对象，不是受击目标。

## 让同行关系成为可操作的环境能力

以下是完整主旅程的设计方案，不是对现有战斗影伴能力的功能声明。每种能力都需要独立的环境对象和状态反馈，不以按 E 次数、原地跳跃次数或提高伤害作为学习证明。

### 森林：把“一起走”变成“我在这里等你”

风铃石会被折纸风掀起。小暖留在石上，桥面才保持安稳；棉棉前往另一侧读取被枝叶遮住的地址。玩家决定先留下小暖，再从可见的小桥通过。脚下的石头亮起邮戳，桥绳由摆动转为绷紧；呼回小暖时，对岸已经开启的捷径仍可使用。

实现单元：伙伴跟随/留守状态、风铃石占用检测、桥口可通行状态、两端安全落点、一次性开启的回程路径。完成依据是玩家在伙伴实际守住石头时跨过桥，而不是发出留守指令本身。未站到石上不会亮邮戳；松开后站在桥上的玩家先被送到最近安全桥头，不能困住或丢失信件。

本轮另一模块正在实现这一最小机制，以及三片地址、靠近栗笺按 F 投递的切片。这里不把正在开发的切片扩展描述成整个森林章节已完成；合并后的真实验证以对应模块测试和实机报告为准。

### 湖泊：让伙伴稳住纸船，自己选择靠岸点

小暖可以系在纸船的船头，抵住侧流；棉棉沿岸拨动两个导流叶片，选择让船靠向地址木夹还是回程码头。这里改变的是可移动平台的路线，并非再放一个需要踩住的开关。泡芙从水面读出岸上看不清的门牌，让她成为解决地址问题的合作者。

实现单元：纸船路径节点、有限流向状态、系绳/解绳交互、靠岸吸附和泡芙的地址提示。玩家通过观察叶片与水纹预测目的地，试错时纸船停回上一个码头；不引入溺水、信件泡坏或重复刷取材料。检验点是没有操纵导流叶片时无法到达目标码头，改变流向后确实产生一条不同路线。

### 山地：把两段铃声接成一个答案

小暖记住一次短铃序列，在山弯另一侧回放；棉棉在可听见却看不全的另一处补上缺少的一声，让岚角的风向牌转向正确岔路。小暖第一次提供棉棉当前所在地无法提供的信息，而不是完全复制移动。

实现单元：最多三个符号的序列、记录/回放状态、字幕与图形同时呈现的铃声、错序无惩罚重置。可以慢慢点按，不考反应时间；听力设置关闭音效也能解。检验点是需要把观察到的序列迁移到另一处使用，随机连按不会直接累计“使用技能”进度。

### 暖沙：共同搬动一小片阴凉

小暖举起遮阳布的一角，棉棉带动另一角，布下的卷叶会舒展开来，露出被挡住的旧门牌。带着遮阳布的移动方向受两端距离约束，玩家要决定先从哪侧绕过石堆，让布面覆盖目标。团刺教两位小邮差把各自的舒服距离说清楚。

实现单元：布两端的位置约束、阴影多边形、遮阴触发的卷叶开合、明确的放下/拾起点。这里移动的是两人共同持有的环境形状；不做掉血的高温计时，也不让玩家为了“治疗”反复等待。检验点是只有布面实际覆盖门牌处才能看清线索，单独按下举布键不能完成。

### 晴雪湾：各走一条路，把一封信接力到家

小暖重走玩家明确记录的短段脚印，在背风侧带动送信滑盘；棉棉从另一条木栈道打开沿途的挡风页。正确分工后滑盘依次停靠，芝麻从终点把它接住。结尾让先前的路径、停留与接力发生组合，小暖以自己的任务参与完成。

实现单元：长度有上限的显式路径记录、暂停/重录、离散的滑盘站点、挡风页状态与安全返回。不要把现有上一局统计画像称为可以精确重播路径或机器学习。检验点是滑盘真的依赖两条路径的协作；失误就回上一个站点，小暖始终在场，成功后也不消失。

这些能力之间应能回访复用。例如纸船可抵达森林湖岸的旧木夹；铃声回放能让邮局旧铃多一段和声；双人遮阳布能成为大家的野餐棚。回访奖励优先给短回信、邮票图案与可见的居民变化，让关系延续成为成长的一部分。数值专精与旧无尽/独立影子试炼保留在支线训练范围，不能冒充这些环境成长已经完成。

## 官方机制参考与本项目判断

《A Short Hike》官方介绍同时给出清晰的山顶目标、标记道路和可自由探索的路径，并让行走、攀爬、滑翔贯穿遇见居民和发现物品的过程。对本项目的启示是：地址给方向，环境动词让沿途值得选择；不需要靠重复战斗量来证明旅程充实。这是我们的设计推断，并非对其隐藏任务数量或通关时长的结论。[A Short Hike 官方网站](https://ashorthike.com/)

《Mail Time》官方 FAQ 将主任务写成寻找收信人具体地址，明确提供自行选路、投递、滑翔和无时间压力的游玩方式。对本项目的启示是：先让玩家真正在地图里读地址、找到居民、交出信，再围绕不同居民扩展环境行动；绘本和收集数量本身不能替代投递操作。[Mail Time 官方 FAQ](https://www.mailtimegame.com/faq)

《Farewell North》官方介绍把牧羊犬与人类同伴同行、探索群岛和恢复颜色放进同一个叙事目标，并列出少量解谜、潜行要素。我们借鉴的是“关系与环境变化共同推进”的组织方式。本作采用自己的主题：明亮的邮路、仍健在的柏叔，以及结尾继续同行的小暖；五地区的具体协作机制均是上文提出的原创方案。[Farewell North 官方网站](https://farewell-north.com/)

## 本轮已经落地的故事层

- `src/data/story.ts`：序章三页、五封回信各两页、终章三页，共七节十六页；五位收信人的地址、心愿和同行主题是可被场景读取的数据。
- `src/scenes/StoryScene.ts`：静态绘本、纸张与邮戳图形、可用时显示 `mailcat-portrait` 猫肖像。没有猫纹理时显示信封，不代用旧角色肖像。鼠标按钮及左右键翻页，R/Home 重看，Escape 随时合上；最后一页继续即退出。
- 重看不写新的“已读”存档、不再次发奖。旧战役按 `stageResults` 连续已通关的 10/20/30/40/50 边界解锁，不能只凭缓存的 `highestUnlockedStage` 打开结局。
- 函数允许调用方提供真实森林投递完成状态；该布尔值只额外解锁栗笺回信，不伪造任何旧战役通关，也不提前开放后四封回信或终章。
- `StoryScene` 和 `LetterBookScene` 注册到游戏；菜单、回信册、投递、结算入口由对应模块接入。五个新地区尚未构成完整可玩主旅程，四种后续环境能力仍是计划。

### 集成契约

```ts
getStoryLibrary(campaign, postalDelivered = false)
// { id, title, chapter: number | null, unlockAfterStage,
//   pageCount, unlocked, recipient: string | null }[]

isStoryUnlocked(id, campaign, postalDelivered = false)
resolveStoryRequest(input, campaign, postalDelivered = false)
getStoryForChapter(chapter) // StoryDef | undefined
getStoriesForCompletedStage(stageId) // 50 同时返回第五封回信与终章

scene.start('StoryScene', {
  storyId: 'prologue',
  returnTo: { scene: 'DeliveryScene' },
});
scene.start('StoryScene', {
  storyId: 'letter-forest',
  returnTo: { scene: 'LetterBookScene' },
});
```

合法返回场景为 `MenuScene`、`CampaignScene`、`LoadoutScene`、`WorkshopScene`、`LetterBookScene`、`DeliveryScene`。只有路线选择与出发准备保留严格限定的导航参数；其余忽略载荷。`StoryScene` 自循环、`ArenaScene`、`GameOverScene` 或未知目的地退回菜单，避免回看故事重新执行战斗或结算副作用。非法或尚未解锁的故事退回序章，但保留合法返回目的地。

正文采用无自动翻页、无逐字等待的短页设计；跳过不能成为损失成长的惩罚。约三小时的实际价值应来自路线探索、每位收信人的可交互变化、逐渐不同的合作能力和一条有结尾的联系链，不能用锁定阅读速度或让玩家空转来补足。

### 验证范围

`src/test/story.test.mjs` 覆盖页数与地址链、短页字数预算、逐章与真实投递解锁、迁移记录兼容、破损进度拒绝、路由载荷过滤、有限翻页及实际 StoryScene 控制器的退出幂等与重入重置。Node 测试使用现有 Phaser 构造边界，不模拟渲染或碰撞；文字行预算只是保守排版约束。最终字体换行、猫肖像裁切、按钮焦点和窗口缩放仍需实际图形界面检查，本任务未启动图形进程。
