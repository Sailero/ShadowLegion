# 策略组件化系统设计构想

> 状态：构想阶段，待讨论  
> 日期：2026-08-13

---

## 一、核心理念

### 当前市场的问题

市面上大多数策略小游戏的策略是**固定的**：
- 玩家只能选择预设的策略（如进攻/防守/平衡）
- 或者直接操控每个单位的微观行为（选中→移动→攻击）
- 策略体验要么太浅（选一个按钮），要么太繁琐（逐个操作）

### 你的博士方向如何创造差异

结合强化学习和多样化策略的学术背景，提出一种新的交互模式：

> **玩家设计策略，单位自主执行**

玩家通过组装「策略组件」来定义单位的行为规则。单位根据这些规则自主行动。玩家的角色从"直接控制者"变为"策略设计师"。

## 二、参考案例

### Gladiabots（机器人竞技场）

- 玩家通过**可视化节点编程**定义机器人 AI
- 条件节点（如"敌人在中距离"）→ 行为节点（如"攻击最近敌人"）
- 支持子 AI 模块复用
- 对战是纯异步的：设计好 AI，观看结果，迭代优化
- 评价："编程但不需要记住语法"

### 值得借鉴的点

| Gladiabots 特点 | 我们可以借鉴/改进 |
|---|---|
| 条件→行为的树状结构 | 更简化：卡牌/拼图式组装，降低理解门槛 |
| 需要复杂调试 | 实时预览 + AI 建议优化 |
| 纯自主对战 | 混合模式：自主执行 + 玩家可随时介入 |
| 无成长系统 | 通过关卡/升级解锁新组件 |

## 三、策略组件系统设计草案

### 3.1 组件类型

```
策略组件分为三层：
┌──────────────────────────────────┐
│ 决策层 (WHEN)                    │
│ 触发条件：何时执行某个行为        │
│ 如：敌人靠近时 / HP低于50%时     │
├──────────────────────────────────┤
│ 行为层 (WHAT)                    │
│ 执行动作：做什么                  │
│ 如：攻击最近敌人 / 后退到安全距离 │
├──────────────────────────────────┤
│ 目标层 (WHO)                     │
│ 选择目标：对谁执行                │
│ 如：最近的敌人 / HP最低的敌人     │
└──────────────────────────────────┘
```

### 3.2 示例：组装一个突击兵策略

```
规则 1: [条件] 攻击范围内有敌人  → [行为] 攻击  → [目标] HP最低的
规则 2: [条件] 无敌人在攻击范围  → [行为] 移向  → [目标] 最近的敌人
规则 3: [条件] HP低于30%         → [行为] 撤退  → [目标] 远离敌人
```

规则按优先级从上到下执行，第一个满足条件的规则被执行。

### 3.3 解锁与成长

| 等级 | 解锁内容 |
|------|---------|
| 1 | 基础条件（敌人距离）+ 基础行为（攻击/移动） |
| 3 | 高级条件（HP阈值、地形）+ 协作行为（掩护/集火） |
| 5 | 目标筛选器（按类型、HP、威胁度） |
| 8 | 组合条件（AND/OR 逻辑）+ 子策略复用 |
| 10 | 全局策略（阵型、资源分配、攻防切换规则） |

### 3.4 与 RL 的深度结合

- **AI 对手使用同样的组件系统**：AI 的策略也是由组件组成的，玩家可以"解读"AI 的策略
- **策略推荐**：基于 RL 模型，向玩家推荐"当前对手可能的弱点"和"推荐的组件组合"
- **自动进化对手**：AI 观察玩家的策略组件组合，自动调整自己的组件来反制
- **多样性奖励**：使用更多种组件组合的玩家获得额外奖励，鼓励探索

## 四、适合的游戏类型

结合以上分析，推荐的游戏类型是：

> **"策略编程 + 实时攻防"的混合模式**

1. **准备阶段**：玩家为每种单位配置策略组件（类似卡组构建）
2. **战斗阶段**：单位根据策略自主行动，玩家可观看或介入
3. **迭代优化**：对战结束后，回顾战斗录像，调整策略组件
4. **渐进解锁**：通过关卡和挑战解锁新的策略组件

这种模式的好处：
- 策略深度极高但操作简单（设计一次，多次使用）
- 天然支持异步 PvP（上传策略，对战不需在线）
- 与 RL 研究深度绑定（组件空间即策略空间）
- 有无限的探索空间（组件组合的多样性）
