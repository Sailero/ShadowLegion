# 第一阶段可玩切片

> 状态：功能与本地验收完成，等待外部盲测通过产品门槛
>
> 基线日期：2026-08-26

## 1. 本阶段回答什么

第一阶段只回答一个问题：**即使不宣传 AI，当前战斗和轻量成长是否足以让玩家完成一局，并愿意尝试另一条构筑？**

本阶段不是正式发行版，也不以内容总量为目标。旧版 3 关 30 波和 30 余项升级被收缩为一条更短、更容易平衡的完整流程。

## 2. 当前可玩闭环

```text
单屏教学
→ 第 1 波熟悉移动、射击、闪避和充能技能
→ 三选一确定爆裂 / 弹幕 / 时隙协议
→ 每波引入一种新威胁和一次流派改装
→ 三次同流派强化触发一次超限进化
→ 第 7 波混编压力测试
→ 第 8 波军团核心 Boss
→ 结算影核、协议首通、战绩与影子行为档案
→ 工坊小幅永久强化 / 换协议重开 / 无尽演练
```

### 战斗内容

| 模块 | 当前实现 | 设计作用 |
|---|---|---|
| 基础操作 | WASD、鼠标按住射击、Shift 闪避、Space 技能 | 保留走位、瞄准、风险和资源时机 |
| 波次 | 单局 8 波，命名与战术提示 | 控制节奏，保证一局有开始、升级、高潮和结尾 |
| 构筑 | 爆裂、弹幕、时隙 3 条协议，各有一次超限进化 | 分别强调范围暴击、持续多弹道、控制生存，并给单局成长一个高潮 |
| 选择结构 | 协议确定后，通常出现 2 张流派牌 + 1 张通用牌 | 兼顾成型感与临场生存选择 |
| 敌人 | 追击、侧翼、远程、重甲、猎杀、召唤 6 种职责 | 迫使玩家改变移动和目标优先级 |
| Boss | 独立血条、召唤、弹幕、带红线预警的冲锋 | 检验构筑，同时保证危险可以归因 |
| 反馈 | 受击闪白、击退、数字、粒子、震动、音效、准星 | 提高清晰度和击杀爽感 |
| 局外 | 影核、三项五级工坊、协议首通、战绩与最佳时间 | 给失败补偿、短期目标和有限的长期积累 |
| 影子档案 | 记录移动、射击、闪避、技能与承伤，输出四维风格 | 让每局留下身份反馈，并为第二阶段建立数据接口 |
| 流程 | 教程、暂停、胜负结算、排行榜、工坊、重开、菜单 | 让 Demo 可交给不了解项目的人独立试玩 |

## 3. 三条构筑的体验承诺

### 爆裂协议

- 开局立刻获得命中爆炸和更高等级能量爆发。
- 后续通过暴击、爆炸强化和技能升级形成范围连锁。
- 三项流派强化后进化为“超新星”，同步提升爆炸、暴击和基础伤害。
- 爽点：少量关键命中引发成片清场。

### 弹幕协议

- 开局获得双弹道和弹幕风暴。
- 后续通过并联枪管、穿透和攻速持续扩大火力覆盖。
- 三项流派强化后进化为“赤色风暴”，追加弹道、穿透和攻速。
- 爽点：从精确射击逐步成长为稳定火力网。

### 时隙协议

- 开局获得时空裂隙和护盾。
- 后续通过减速、护盾、闪避冷却形成控场与机动循环。
- 三项流派强化后进化为“永恒时隙”，追加护盾、迟滞和闪避循环。
- 爽点：在高压弹幕中主动制造安全窗口。

构筑通过的判断不是最终 DPS 接近，而是盲测玩家能从画面和操作中说出三者差异。

## 4. 局内与局外爽感怎样连接

当前采用三层成长，不依靠无上限数值填充内容：

1. **秒级反馈**：命中、暴击、击退、清场、能量技能与掉落构成即时爽感。
2. **单局成型**：先选协议，再用流派牌累积方向，三次同流派强化触发一次可见进化，保证 8 波内出现能力跃迁。
3. **跨局目标**：每局按进度获得影核；通关和首次用某协议通关给额外奖励；工坊的武器、装甲、电池各五级，最终上限为伤害 +15%、生命 +25、初始充能 +40。

局外成长只让开局更顺，不替代走位、闪避、构筑和 Boss 处理。三条工坊总计 60 影核，可形成一个有限的原型目标；若盲测显示玩家只为数值重复游玩，应降低其权重，转向影子外观、称号与挑战收藏。

结算同时生成“火力、机动、反应、技巧”四维档案和风格标签。第一阶段它只用于反馈与留档，不声称已经生成智能队友或对手。

## 5. 已完成的工程验收

- `npm run build` 通过 TypeScript 检查和 Vite 生产构建。
- 生产 JS 约 1.59 MB，gzip 约 373 KB；目前尚未加入正式美术和音频资源。
- 浏览器数据测试 21/21、场景测试 29/29。
- 浏览器无 console error / warning。
- 人工走查了菜单、教程、射击/闪避、三选一、三条流派卡池、波次提示、Boss 血条和冲锋预警、暂停、胜利结算、影子档案、工坊购买与重开。
- 修正了 Boss 出场后立即攻击的问题：其攻击计时从出生时开始，首个预警不会与登场提示同时触发。

## 6. 尚未被证明的部分

“功能可玩”不等于“市场上好玩”。以下内容必须由非开发者验证：

- 真实一局时长、前半局是否拖沓、Boss 数值是否合理。
- 射击、闪避和技能是否在没有解释时也足够清楚。
- 三条构筑是否都能成型，是否存在明显唯一最优解。
- 玩家死亡是否能归因，红线和远程弹道是否有足够反应时间。
- 结束后是否真有尝试另一协议的欲望。
- 超限进化是否能在正常游玩中稳定出现并被看懂；影核速度是否既有目标又不强迫刷取。
- 工坊是否改善成长动机而没有造成“升级前故意难受”；影子档案是否让玩家产生身份兴趣。
- 当前程序化图形和音效是否已达到“可接受原型”，而不是被误认为最终品质。

微信触控、真机性能、平台生命周期、正式美术、商业化、联网、智能影子队友/对手均不属于第一阶段完成项。局外成长的最小闭环已经完成；更多角色、装备、任务和收集留到方向验证之后。

## 7. 盲测方案与门槛

先做 5 人问题发现，再做 10–20 人方向验收。测试者不提前阅读设计文档，也不告知未来 AI 卖点。

### 自动记录

- 是否完成教程、到达波次、胜负、用时、击杀、协议。
- 已记录：技能、闪避、射击、移动、承伤和最终协议，并生成本地行为档案。
- 后续补充：死亡来源、每次升级选择、进化触发时间和工坊购买路径。

### 目标门槛

| 指标 | 第一轮目标 |
|---|---:|
| 独立完成教学并正确说出四个操作 | ≥ 80% |
| 第 2 波前退出 | < 15% |
| 首局到达 Boss | ≥ 50% |
| 首局通关率 | 25%–45% |
| 能说出至少两条构筑的差异 | ≥ 70% |
| 正常通关者能说出本局的进化变化 | ≥ 70% |
| 主要死亡原因可正确复述 | ≥ 80% |
| 结算后愿意立刻换协议再玩 | ≥ 50% |

通关率只是难度信号，不是唯一目标。若通关率合适但重开意愿低，仍判定基础循环未通过。

### 只问五个问题

1. 哪一刻最爽，哪一刻最无聊？
2. 你为什么死，下一次会怎样处理？
3. 你选了什么协议，它具体改变了什么？
4. 如果马上再开一局，你会换什么，为什么？
5. 你是否愿意再玩？0–10 分，低于 7 的原因是什么？

## 8. 进入第二阶段的决定

- 达到门槛：冻结基础规则，只修平衡和明显体验问题，开始“通用副手 vs 个性影子副手”A/B 原型。
- 接近门槛：最多做两轮定向修改，优先修首波节奏、死亡可读性和构筑质变。
- 明显未达标：不开发学习型 AI 或联网；先决定是改善射击手感、改为自动瞄准，还是更换基础战斗框架。
